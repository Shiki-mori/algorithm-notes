## 掌握建议：338. Counting Bits

- 范围：整题（官方四解）
- 总体：建议掌握
- 主推解法：DP 最低有效位 — 建议掌握

### 笔试

`n ≤ 10^5`，`O(n log n)` 就能过。限时优先写 **DP 最低有效位**：`bits[i] = bits[i >> 1] + (i & 1)`，一行递推、几乎无边界。写不出来再退 **Brian Kernighan**（对每个数 `n &= n - 1`），同样稳过。不要在考场维护最高有效位。

### 面试

先报逐个数 1 的 `O(n log n)`，再落到线性 DP。主讲最低有效位：右移丢掉最低位，奇偶决定是否加 1。追问「和 Kernighan 什么关系」时用最低设置位：`bits[i] = bits[i & (i - 1)] + 1`。最高有效位能说「减去最近的 2 的幂」即可，不必当主讲。

### 各解法

| 解法 | 等级 | 一句话理由 |
| --- | --- | --- |
| DP 最低有效位 | 建议掌握 | 代码最短、易写对，笔试面试都当主解；`>>` / `&` 是后端位运算基本功 |
| Brian Kernighan | 必须讲清 | `n & (n-1)` 可迁移到 191、判断 2 的幂；本题复杂度不是最优，面试常被要求再压到 `O(n)` |
| DP 最低设置位 | 必须讲清 | 就是把 Kernighan 的结果复用成线性 DP，常见追问，不是第一笔写法 |
| DP 最高有效位 | 了解即可 | 同是 `O(n)`，但要维护 `highbit`，易写错，迁移价值不如另外两档 DP |

当前仓库代码有 `countBitsBrianKernighan`、`countBitsHighBit`，没有最低有效位 / 最低设置位；另有 `Integer.bitCount` 和逐位右移。题面禁止内置函数，API 版面试不要交。

### 投入

- 先做：默写最低有效位那一行，并能口述 Kernighan 如何升级成最低设置位
- 可后做 / 可放下：最高有效位不用反复刷；逐位右移只作引入，API 版放下

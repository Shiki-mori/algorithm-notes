# 题解：Max Consecutive Ones III

## 思路

对于[l,r]，只要包含不超过k个0，就能构造出长度为r-l+1的连续1区间。

#### 问题转化为：

对于任意的右端点r，要找到最小的左端点l，使得

[l,r]包含不超过k个0 。

#### 判断[l,r]中0的个数

将1和0互换。

对原数组求前缀和。

记P[i]为第i个数的前缀和（即P[0]~P[i]）

则[l,r]中0的个数为：

P[r]-P[l-1]

枚举r，找出最小的满足条件的l。

原数组仅包含0，1，因此前缀和一定单调，可二分查找l。

#### 为什么前缀和单调就可以二分l

二分的依据不是「枚举时l从左往右、所以l递增」。对每个固定的r，要在[0,r]里找最小的l，使P[r]-P[l-1]≤k。

P不下降，l变大时P[l-1]只增不减，0的个数只减不增。判定「0的个数≤k」只翻转一次：

- l太小，窗口太长，0太多，不可行
- l一旦够大，再往右缩，0只会更少，一直可行

可行的l是一段后缀[l*, r]，可以用二分定位l*。每个r单独二分，时间O(n log n)。

「r右移时最优l不回头」是另一件事，它让滑动窗口能做到O(n)，不能用来论证对l二分。

若数组含负数，前缀和不单调，P[r]-P[l-1]≤k会随l来回翻转，可行l不再是连续后缀，二分会丢答案。例如nums=[-3,1,1]，k=0，r=2：

- l=0，区间和-1，可行
- l=1，区间和2，不可行
- l=2，区间和1，不可行

最小可行l是0。二分在中点l=1看到不可行，会按单调性丢掉左半边，得到无解。

#### 前缀和构造（错误）

P[0]=0
P[i]=P[i-1]+nums[i]

错在两处：

1. 前缀和累加的是 0 的个数。前面已经把 1 和 0 互换，增量是 `1-nums[i]`，不是 `nums[i]`。
2. `P[0]=0` 只能表示「下标 0 之前」的哨兵。这时数组长度是 n+1，`P[i]` 表示 `nums[0..i-1]` 里 0 的个数。若仍用前面的定义「`P[i]` 覆盖 `nums[0..i]`，个数为 `P[r]-P[l-1]`」，则 `P[0]` 必须等于 `1-nums[0]`，不能恒为 0。

#### 前缀和构造（正确）

用长度 n+1 的哨兵，二分时不用访问 `mid-1`。

P[0]=0
P[i]=P[i-1]+(1-nums[i-1])，i=1..n

[l,r] 中 0 的个数为 P[r+1]-P[l]。

#### 二分查找（错误）

对于固定好的r，寻找符合条件的最小l。
二分查找l
上界 r
下界 0
preSum[lr]-preSum[mid-1]>k 
->preSum[mid-1]<preSum[lr]-k
preSum[mid-1]与mid正相关，说明target在右半区间，往右找。
ll=mid+1
preSum[lr]-preSum[mid-1]<=k 符合条件，找更小的
lr=mid-1

大于 k 时往右找，这个方向是对的。错在：

1. `preSum[lr]` 把二分上界 `lr` 当成了固定右端点 r。`lr` 收成 `mid-1` 之后，比的就不再是以 r 结尾的窗口。右端点始终用 r。
2. 条件成立时 `lr=mid-1` 会把当前可行的 mid 丢掉。找最小 l 时，mid 自己可能就是答案，应保留：`lr=mid`。
3. 笔记没有写答案从哪读。最小 l 是循环结束后的 `ll`，并且还要再检查 `[ll,r]` 是否真的可行；可行才用 `r-ll+1` 更新长度。不能在循环里用搜索边界 `lr-ll+1` 当窗口长度。

#### 二分查找（正确）

对固定的 r，在 [0,r] 上二分最小的 l，使 P[r+1]-P[l]≤k。

ll=0，lr=r

while ll<lr:

mid=ll+(lr-ll)/2

P[r+1]-P[mid]>k：l 太小，窗口里 0 太多，ll=mid+1

否则：mid 可行，更小的 l 仍可能可行，lr=mid

循环结束时 ll 落在 [0,r]。若 P[r+1]-P[ll]≤k，用 r-ll+1 更新最大长度。整个 [0,r] 都不可行时（例如 k=0 且 nums[r]=0）不更新。

- 能二分l，是因为固定r时「0的个数≤k」随l单调；依据是前缀和不下降，不是l随扫描递增。

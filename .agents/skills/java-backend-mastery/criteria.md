# 判断标准

服务对象：Java 后端校招/社招笔试 + 面试，不是竞赛，不是算法岗。

## 笔试 vs 面试

| | 笔试 | 面试 |
| --- | --- | --- |
| 看重 | 限时写对、边界、复杂度别爆 | 思路、对比、复杂度、能改约束 |
| 主解偏好 | 好写、不易错、能过数据范围 | 最优或次优 + 说得清为什么 |
| 降档 | 易写爆、调参多、数学细节易错 | 只会 API 说不清原理、只会暴力 |

一题两套结论可以不同：例如组合数「笔试了解即可，面试必须讲清」。整题总体仍按主推解法。

## 定档口诀

先定主推解法，再给旁支降档。

- **必须手写**：国内 Java 后端笔试/面试高频模板，或本题唯一稳妥过测的写法。换公司仍用得上。
- **必须讲清**：常被追问的最优解、空间优化、或与主解的对比；默写易错（组合数溢出、快选边界）则强调讲清而非死记。
- **建议掌握**：中频或加分（单调栈、Trie、区间贪心、并查集）；时间紧可排后，但比「了解」值得练。
- **了解即可**：用来引入、对照或展示另一种视角；不当主解，不必反复刷。
- **可以跳过**：纯暴力必 TLE、竞赛剪枝、与后端岗迁移价值低的数学/位运算炫技。

## 多解法怎么排

1. 笔试主推：代码短、边界少、Java 标准库能写完。
2. 面试主推：通常与笔试相同；若存在明显更优解，面试要能讲，笔试仍可写好写的那版。
3. 引入解（未优化 DFS/暴力）：了解即可。
4. 手写底层（手写堆、手写哈希）：有 API 替代则降到必须讲清或了解即可；本题题解若在教原理，面试讲清即可。
5. 数学闭式：面试能说「是组合数、怎么推、和 DP 等价」即可；默写连乘除防溢出算加分，不抬成必须手写，除非用户点名该解法且笔试数据范围逼你用它。

## 题型基线（可按本题偏离）

上调：约束大必须优化、标签是后端高频、同一模板能带走很多题。
下调：偏实现细节、偏数学、偏竞赛、或只是学习计划里的填充 Easy。

| 方向 | 默认整题/主解 |
| --- | --- |
| 哈希、双指针、滑动窗口、前缀和 | 必须手写 |
| 链表（反转、快慢指针）、栈、队列 | 必须手写 |
| 树 DFS/BFS、BST 基本操作、图 BFS | 必须手写 |
| 堆：`PriorityQueue` 用法 | 必须手写 |
| 二分（数组 / 答案上二分） | 必须手写 |
| 一维/网格/双串 DP（路径、LCS、背包入门、打家劫舍） | 必须手写 |
| 回溯（子集/组合/电话号码） | 必须手写或建议掌握（看数据范围） |
| 贪心区间、单调栈 | 建议掌握 |
| Trie、并查集、拓扑 | 建议掌握 |
| 编辑距离等较重 DP | 必须讲清；手写视时间 |
| 手写堆下沉、快选细节、组合数公式 | 必须讲清或了解即可 |
| 复杂位运算、冷门数学 | 了解即可或可以跳过 |

## 读本题材料时看什么

- `Problem.md` 难度/标签/约束：Easy 高频模板仍可能必须手写；Hard 且冷门可降档。
- 数据范围：决定暴力能不能过，从而决定「了解即可」还是「必须手写优化」。
- Java 多个 public 方法 = 多种解法；`Solution.md` 小节标题与方法名对上。
- 本仓库不少题来自 LeetCode 75：当「后端岗该不该会」的弱信号，不单独抬档。
